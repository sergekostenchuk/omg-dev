## 3. Предотвращение первой переделки

Зарегистрированных отказов L3 нет. Названные классы из предыдущих этапов применяются к его исходному контракту:

1. **Сохранять верхние уровни и идентичность.** composeLayer наследует version/id/title/actors/requirements и проверяет равенство L1/L2-проекции. Модель не переписывает эти данные независимо. Schema описывает собранный результат; при pilot delta передаются изменения относительно точной базы, как в L2.
2. **Атомарность определяется результатом потребителя.** Активные узлы horizon имеют kind=work, с понятным outcome, пользой и границей ответственности. Модель выбирает содержательные границы; код привязывает системные идентификаторы.
3. **Code refs честно разделяют existing/planned.** Относительный путь будущего модуля не выдаётся за существующую реализацию. Boundary work сохраняет полномочия, writer и rollback соответствующей operation. Предложения о новом проекторе не требуют предъявить готовый код до его задачи.
4. **Нужные зависимости не теряются при сужении.** Для затронутых верхних connectors сохраняются producer и consumers в L3 bindings; у активного входного порта есть producer. Выход к будущему потребителю требует предусмотренной спящей связи. Неизвестная зависимость не подменяется фиктивным ready.
5. **Тест относится к тому же результату.** Test принадлежит своему node, covers содержит connectors. Команда, given/when/then, forbiddenEffects, entrypoint и counterfactuals образуют один контракт. Durable требует cold-read/restart, provider — provider_safety; exclusive-ресурс должен быть назван. Это требования проекта проверки, не выполненный тест.

Основания: `graph/layer-design.ts:11–58`, `graph/validate.ts:140–156`, `graph/semantics.ts:35–39,69–77`, `graph/obligations.ts:3–9`, `compiler/derive.ts:15–66` на d88.

**Размер первой попытки:** время, input/output и объём evidence определяются выбранным work-набором и полной доставкой нужных оснований. Нельзя автоматически переносить ни маленький старый reply cap, ни стоимость уже испорченного L2-прохода. При большом проекте использовать сохраняемые части согласованной delta; достаточный начальный бюджет допускается.

## 4. Первый пакет и повторяемость

Фактического request нет; размер и побайтная доля повторов неизвестны. В будущий пакет нужны завершённые exact R2/L2 основания, scope, выбранный результат, применимые source refs/репозиторные сведения и полный контракт выхода. Первичные материалы не заменяются только названиями файлов или предыдущими резюме.

Код заранее предоставляет известные ссылки, допустимые поля и отношения; модель определяет атомарные результаты, необходимые связи и смысл проверок. Полезное неразрешённое исследование сохраняется и адресно возвращается в R2. Ненужный поиск schema, ID или очевидного диапазона не должен становиться отдельным платным действием.
