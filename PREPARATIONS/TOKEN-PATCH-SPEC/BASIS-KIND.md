## Изменение до первого вызова
1. Контракт: у факта источник типизирован (repository-file / owner-document / document-observation); многофайловое основание — массив типизированных источников или отдельные атомарные факты, не строка с разделителем (2.5): `{kind: "repository-file", sourceIndex}` либо `{kind: "owner-document", sourceIndex, quote}`. Path подставляет движок по sourceIndex, как у читателя; модель path не пишет.
2. Валидатор: три вида основания с разными пределами. repository-file (источник file, sourceIndex) допустим как fact. owner-document (источник owner-document, sourceIndex, quote обязательна) допустим как основание design / decision, недопустим как repository fact и как runtime proof. document-observation (тот же источник owner-document, quote обязательна) это наблюдение «сообщено, в репозитории не подтверждено»: допустимо как основание gap или design с явной пометкой и ссылкой на обязательство «подтверждение среды» (вид знания из CASE-4.0), недопустимо как repository fact и как закрытие обязательства о живом исполнении. Третьего вида источника нет: в базе только origin.kind file и owner-document (`evidence.ts:9–10`). Сообщение отказа называет ожидаемый вид.
3. Промпт аналитика: описать три вида основания и запрет писать path руками.

Вид изменения: контракт + код валидатора + промпт.
