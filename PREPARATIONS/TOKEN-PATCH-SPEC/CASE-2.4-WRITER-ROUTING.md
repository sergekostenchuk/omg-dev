## Дефект
Аналитик выбирает файлы для чтения по названию, а не по статически известным связям: по задаче о записи читает модуль построения значения (builder), хотя писатель импортирован и вызван рядом; по задаче о повторе получает вызывающую функцию без тела вызываемой, лежащей в том же файле строками выше. Недостающее покупается отдельной парой аналитик + читатель.

## Место в коде (d88b89c)
- Сборщик источников `ResearchSources` (`src/discovery/reader.ts:96–104`): читает пути, поданные моделью, без разрешения импортов и вызовов.
- Инструкция читателя (`reader.ts:115`): «включая применимые условия, исключения и необходимый соседний контекст», но выбор ограничен поданным пакетом.

## Изменение до первого вызова
1. Код до читателя: ограниченный статический обход от выбранного (уточнено 2026-09-07, п.10): глубина 1, только относительные импорты выбранных файлов и функции того же файла, вызываемые из выбранного диапазона; не больше N файлов (N в профиле); ёмкость пакета считается кодом до вызова (CASE-2.0, п.3). Средство: `typescript` 6.0.3 (package.json:23), разбор файла компилятором, без регулярных выражений. Динамические вызовы → запись `{kind:"unresolved-call", from, expression}` в пакете, явное неизвестное. Найденные файлы это кандидаты с пометкой `origin:"static-link"`, не утверждение «вот писатель»; суждение остаётся аналитику.
2. Промпт аналитика: формулировать задачу через символ (кто пишет, кого вызывает), а не только через имя файла.
3. Ёмкость расширенного пакета считать заранее (CASE-2.0-READ-BUDGET): более полный пакет не должен упираться во входной лимит.

Вид изменения: код сборщика + промпт.

## Тест
- Пакет с engine.ts и задачей «кто записывает граф» получает repository.ts в связанный набор без второго вызова аналитика; мутация: убрать разрешение импортов — тест обязан упасть.
- Выбор диапазона внутри ensureWorktree добавляет в окно materializeWorktree того же файла.
- Обход останавливается на глубине 1 и на N файлах; мутация «снять ограничение глубины» — тест на размер пакета обязан упасть. Динамический вызов даёт запись unresolved-call, а не молчание.
