## Дефект
Один параметр профиля `maxReplyChars` ограничивает две разные величины: размер координатного ответа читателя (selections) и размер извлечённых по этим координатам оригиналов в canonical-обвязке. Координатный ответ короткий, извлечение в десятки раз больше. При превышении кандидат отбрасывается до записи reader-result: оплаченные вызовы аналитика и читателя пропадают, следующий шаг — новый подбор источников и новый читатель.

## Изменение до первого вызова
1. Профиль: отдельный параметр `maxExtractedChars` в схеме `reader-pilot.ts:13, 29`; `research-limits.ts:13` возвращает его для extractedChars. Это размер страницы доставки извлечения в рабочее множество, а не потолок записи reader-result (запись целиком, сверху ограничена входом `maxReadChars` плюс обвязка). `maxReplyChars` не трогать: он общий физический потолок ответа любой роли (`research-protocol.ts:193–197`), и проектный ответ L2 требует 100 000. Начальное значение страницы не ниже максимального наблюдённого извлечения 40 809 (2.6, T76); верхняя граница из `maxContinuationChars` минус обязательная часть продолжения. Исправлено 2026-09-07 по обсуждению, п.3.
2. Код: при превышении лимита извлечения не отвергать, а записывать reader-result с полным manifest выборок (sourceIndex → Ref, диапазоны строк) и выдавать оригиналы страницами существующим механизмом `contextPage`. Непереданные части хранятся явно, не отбрасываются.
3. Код до читателя: размеры источников известны движку (`contextCatalogue` хранит chars); связанный пакет, не помещающийся во вход, разбивать кодом по границам файлов и обработчиков до первого вызова, а не после отказа (2.2, T192).
4. Повторное использование уже наблюдённых диапазонов — вынесено в CASE-2.3-OBSERVED-REUSE (2.3, 2.8). Кратко: в 2.3 три из четырёх источников T52 уже были наблюдены в отрицательной оценке T50; сегодняшний кэш reader-result (`reader.ts:105–108`) ищет совпадение по вопросу, цели и покрытию, поэтому не срабатывает. Нужен поиск по уже сохранённым наблюдениям тех же версий источников.
5. Ограничение: не уменьшать исследовательский охват ради порога; выбор источников остаётся за задачей вопроса. Кандидат без измерения (2.2): выбор читателя целыми строками тянет разметку вместе с обработчиком (ui/app.tsx, строки 145 и 155 по 900+ знаков); точные смещения внутри строки с сохранением охватывающих условий — отдельная правка, эффект не измерен.

Вид изменения: код + ревизия профиля. Промпт читателя не меняется.
