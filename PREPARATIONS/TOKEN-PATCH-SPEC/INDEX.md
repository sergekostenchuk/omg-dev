## Порядок посадки (предложение)
1. CASE-2.0-READ-BUDGET и BASIS-KIND: локальные, не меняют состав пакета, снимают повторные подборы и отвергнутые ответы.
2. TYPED-ADDRESSING: контракт отчёта; меняет формат выхода модели, требует правки промпта.
3. CASE-1.6-DELIVERY: меняет состав первого пакета; мерить после первых трёх, иначе рост пакета смешается с их эффектом.
4. REPEAT-LOOP: внутренний путь синтеза подтверждён в 4.0; посадка не должна ждать 4.1–4.13.
5. CASE-4.0-OBLIGATION-CONTRACT: решение владельца по контракту области и приёмки R2; без него повтор R2 упрётся в ту же стену независимо от механики.

## Условие приёмки для всех карточек
Повтор одного поля R1 (productDomain, запись 2.1 как база) в живом прогоне с журналом model-call. Сравнивать классы вызовов «полезный / переделка / справка / петля» с таблицей записи 2.1, а не сумму токенов вообще. Экономия объявляется только по разности классов «переделка» и «справка» при том же принятом результате.
