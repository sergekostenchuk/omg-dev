1. Спецификация вопроса получает список требуемых входов `requires: [{ref, pointer}]` из контракта поля; сборщик (research-runner) разворачивает их оригиналы в первый пакет до вызова сильной модели, используя адреса `contextCatalogue`.
2. Не копировать весь канон в каждый вопрос: набор определяется потребителем поля.
3. Декларации внешних систем не считать доказательством runtime.
4. Вид изменения: контракт спецификации вопроса + код сборщика. Промпт не меняется.
