## Изменение до первого вызова
1. У каждого активного обязательства: обоснованная связь с результатом области, ответственный вопрос (один), этап разрешения и вид разрешения (факт репозитория / проектное решение / подтверждение среды до исполнения / доказательство после реализации).
2. Согласовано с Codex 2026-09-08 (канал POST-AUDIT-OMG seq 7–9, 9/10), ждёт подписи владельца. Пять видов знания у обязательства в записи research-scope: repository-fact (утверждение о состоянии снимка, требующее доказательства; «не найдено» допустимый типизированный исход), design-decision, owner-decision (известное решение владельца по точному источнику; need_owner это действие при его отсутствии), environment-confirmation, post-implementation-proof. Отдельно от вида область задаёт момент обязательного разрешения: R2-сейчас | при R3 (refinement assess до ready) | перед началом названной задачи | при принятии её результата (execution requireGates, commit.ts:16 / result.ts:25). Модель не выбирает ни вид, ни момент. Необходимое для текущего решения R2 не откладывается независимо от вида; environment-confirmation переносится только при доказанной независимости текущего решения и с точным последующим потребителем; конфликт с исходным requiredFor=current показывается владельцу, next/current не правятся. Перенос содержит идентичность (carried на обязательство точной ревизии scope), ответственного, причину, условие возврата (wake), момент. Ворота post-implementation-proof: принятие результата реализующей задачи, не принятие плана; compilation переносит обязательство в контракт проверки задачи. Область применяется одной ревизией после раскладки всех 33 активных + 34-го отложенного; частичных подписей нет. Условие применения: оплаченные материалы прежнего черновика (checkpoint, saved-synthesis, reader-result привязаны к точной ссылке вопроса: saved-synthesis.ts:7–13, reader.ts:108) переносятся на новый черновик по тождеству источника/поля, а не теряются. Факт: код scope_deferral_invalid существует, но полей kind / moment / gate / carried и их проверок в ResearchScope нет; это реализация P1.
3. Порядок зависимостей вопросов согласован с областью; первый вопрос не обязан закрывать пробелы чужих групп. Пробел, повторяющий тему чужой группы, оформляется как ссылка «исходное обязательство → вопрос-владелец → нужный вклад», и зависимый ответ не пересочиняется, пока единственное изменение — та же неразрешённая зависимость (4.1).

Вид изменения: контракт области и приёмки (валидатор) + промпт вопросов R2.
