## Дефект
Контракт генерации слоя L2 поручает модели независимо описывать связи разных типов: test.covers (нужны id коннекторов), test.node и обратный node.tests, набор обязательных requirements по выбранному outcome, наличие join при трёх и более входах. Модель путает journey и connector, приписывает групповой тест чужим узлам, не переносит требования outcome и не описывает join. Валидатор ловит это уже после оплаченного проекта: десятки производных находок из четырёх причин и вторая delta.

## Изменение до первого вызова
1. Типизированные ссылки в схеме генерации: connectorRef и journeyRef — разные типы; covers принимает только connectorRef; counterfactual привязан к тому же набору.
2. Владелец теста один (`test.node`); участники в типизированном `test.participants: [nodeRef]` (владелец не входит). `node.tests` код выводит только для владельца; для участников производное `node.exercisedBy: [testRef]`, не покрытие их результата. Определено 2026-09-07, п.16 обсуждения.
3. Обязательный набор requirements по выбранному outcome подставляет код; модель не переписывает известное множество.
4. Необходимость join по входящим connectors определяет код и до вызова проектировщика формирует запрос «узел X, входы A, B, C: условия соединения, обязательные/необязательные входы, отказ, восстановление»; модель отвечает только этими полями, тождества входов подставляет код; после `composeLayer` условия join сохраняются побайтно (canonical равен присланному), код их не нормализует. «Все входы обязательны» по умолчанию не ставится (восстановление повреждённой базы не должно читать повреждённую базу).

Вид изменения: контракт генерации + код сборщика слоя + промпт проектировщика.

- node.tests выводится из test.node: delta без node.tests собирается корректно.
- Узел с тремя входами без join получает от кода запрос на описание join до вызова валидатора; присланные условия после `composeLayer` равны присланным; мутация «нормализовать условия» — тест обязан упасть.
