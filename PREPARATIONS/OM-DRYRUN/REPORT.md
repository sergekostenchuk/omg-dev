**Почему растёт ×2–3 на попытку** (src/om/input.ts:795–860 и цепочки профиля):
1. Кэш доказанных исторических чтений (`view.proven`) живёт одну синхронную операцию. Каждый шаг H1 начинает с холодного кэша и заново выводит всю историю: B1, D1, маршруты, пакеты, вызовы, закрытия и диагностику всех прежних попыток, журнал отказов.
2. Попадание в кэш тоже не бесплатно. `currentFootprint` перечитывает весь транзитивный след доказательства (get/list/history) и для каждой записи считает canonical плюс sha256. След доказательства включает следы всех вложенных — это 53–59% шага.
3. Вывод серии рекурсивен: readSeriesHistory → mechanismResult → deriveManagedClose каждой попытки → её вызов, пакет, диагностика → resolveSeries/readAnySeriesAt снова по той же серии. Новая попытка добавляет уровень вложения и новые доказательства, и каждое из них несёт след всех предыдущих. Число доказательств и размер следа растут вместе, отсюда рост на попытку быстрее линейного.
4. Сверх №34–№36: `checkedLedger` — журнал вызовов общий для прохода. Допуск каждого нового вызова заново выводит все прежние вызовы с историями их серий, поэтому первая попытка новой серии уже стоит 7 мин. Рост идёт и по серии, и по всему проходу.

- Вызовов: минимум ≈ 14 (13 партий + 1 оценка факта репозитория). Реально 20–40: продолжения need_source, повторы (+~2 тыс. знаков на повтор), A6 по ~89 тыс. знаков на каждую неудачную серию. Выход модели не оценивался.
