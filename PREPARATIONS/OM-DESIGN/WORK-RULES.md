# Правила работы над уровнем 2 карты OM-DESIGN (записаны 21.09.2026 по вопросу владельца)

Назначение файла: записанная цель, с которой можно сверять действия исполнителя (в том числе будущему сигнализатору).

## Главная цель
Сдать ПЛАН-СХЕМУ блока OM уровня 2 — правила, передачи между единицами и места, которые обязательно учесть, — так, чтобы ревьюер принял её
по согласованному критерию (журнал ревью №116–117), а тому, кто будет писать модуль, не пришлось самому выбирать поведение продукта.
НЕ цель: рабочий код модуля; исправный черновик.

## Продукт задания
1. Текст правил: `level2-rules.mjs` → карточки группы «Уровень 2 · ПРАВИЛА И ПЕРЕДАЧИ» на полотне и `LEVEL2-RULES.md`.
2. Карточки решений владельца — названный выбор, который нельзя делать в коде.
3. Связи между карточками на карте.

## Инструменты
| Инструмент | Для чего | Чего нельзя |
|---|---|---|
| Чтение кода движка (`src/`, `dist/`) и живых данных | правило опирается на действующую семантику | править `src/`; писать в базу |
| Пробный код `proto/` | прибор под ОДИН вопрос: «сходится ли правило с движком?» | чинить ради ревью; добавлять механизмы; сдавать на ревью; считать тесты результатом |
| Скрипты карты (засев, экспорт, импорт, проверка) | доставить текст на полотно одной цепочкой с остановкой при ошибке | трогать UI |
| Журнал ревью `~/.asvp-review` | запрос полным текстом, предмет — правила | перечислять в запросе тесты вместо правил |
| git | коммит | push, слияния |

## Правила
1. Перед действием назвать, какому правилу или передаче оно служит. Нельзя назвать — не делать.
2. Любая находка сначала становится правилом или местом действия в тексте; код — только чтобы проверить, сходится ли правило с движком.
3. Исправление требует выбрать СМЫСЛ ограничения — это карточка решения владельцу, не код.
4. Статус — по вердикту: «принято» только при «принять»; после трёх «вернуть» — стоп и доклад владельцу.

## Сигналы ухода от цели
Считаются без модели:
- за последние десять действий правок в `proto/` и тестах больше, чем в тексте правил;
- новая функция в `proto/` без нового правила в тексте;
- предмет запроса на ревью — файлы кода или число тестов;
- правка в `src/`.
Требуют понимания текста (классификатор):
- в карточке записано описание кода, а не правило;
- слово «закрыто» или «сдано» без вердикта «принять».
Сигнал идёт владельцу или ведущей сессии, не исполнителю.
