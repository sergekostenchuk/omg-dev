# Уровень 2 карты OM-DESIGN — правила и передачи (предмет ревью)

Собрано из `level2-rules.mjs` скриптом `seed-level2-rules.mjs`; тот же текст — в карточках группы «Уровень 2 · ПРАВИЛА И ПЕРЕДАЧИ» на полотне. Правится только источник.

## Правила · Общие требования и как это читать

```text
КАК ЧИТАТЬ (слова владельца 21.09.2026: «это план-схема будущего кода — нужны правила и места, которые обязательно учесть»; способ ревью согласован с Codex, журнал №116–117)
Предмет ревью уровня 2 — карточки этой группы: общие требования, две передачи между единицами и правила пяти единиц. Карточки функций (F1.1 … F7.4) и папка proto/ — ПРИЛОЖЕНИЕ: они показывают, что правило сходится с действующим кодом движка. Исправность чернового кода условием принятия схемы не является.
«Принять схему» = существенные решения определены; соседние единицы согласованы; тому, кто будет писать модуль, не придётся самому выбирать поведение продукта. Это не обещание отсутствия ошибок в будущем коде.
Блокирует: конкретное противоречие, недостающее решение или путь без определённого поведения — с примером. Если для устранения примера надо менять правило, состав данных или договорённость между единицами — это замечание к схеме. Если правило уже запрещает такое поведение, а черновик его нарушает — это замечание к черновику, схему оно не возвращает.

ОБЩИЕ ТРЕБОВАНИЯ — каждое с местами, где обязано действовать

Т1. Принятое читается из записи, а не угадывается заново. Где записи нет — вывод по действующим отношениям движка; неоднозначность — типизированный отказ, «первый подходящий» не выбирается.
  Места: соответствие «обязательство → конец связи» в каркасах операций и работ; адрес соседа в пакете задачи; основание готовности блока (M2 → M7); адресация вопроса (M5).

Т2. Отношения между узлами — действующая семантика движка, а не приближение. Уточнение = вложенность ИЛИ явное «реализует» (RefinementRelations). Необходимые предшественники = связи данных + requires + передачи владения (controlPredecessors). Годность квитанции — формула компилятора. Владение путём — правила writeGrants.
  Места: замыкание горизонта; принадлежность заполнения верхнему узлу; зона работ; план исполнения; адрес соседа; сверка доставки.

Т3. Производная запись проверяется повторным выводом из зафиксированных источников, а не по собственным полям.
  Места: набор пробелов (G4, G4b); пакеты соседей (G5); кандидат слоя — принимается только граф из записи кандидата (G3, G5).

Т4. Отсутствие — типизированный отказ с адресом. Нет обязательного источника, поля или набора — отказ; значений по умолчанию у обязательного нет; «пусто» передаётся явно.
  Места: вход M1 (правило эры: в записи прежней эры отсутствие структурированного поля — адресный пробел, в новой — отказ производителю стадии); готовность блока в горизонте; источники M5; аргументы всех ворот.

Т5. Переход состояния проверяет, из какого состояния идёт. Повтор того же — без изменений; противоречащее — отказ; запоздавшее не отменяет более позднего.
  Места: принятие кандидата; переход каркаса на новую базу; адресация вопроса; закрытие линии пробела; переход серий; закрытие вызова модели; смена выделения бюджета.

Т6. Порядок записей ничего не решает, кратность доезжает до потребителя.
  Места: несколько привязок одной связи (потоки); несколько потребителей; работа, уточняющая несколько операций; адреса внешних входов; ровно один пакет на работу.

Т7. Проверка и запись — одна транзакция с охраной по точным ссылкам; окна между «проверил» и «записал» нет.
  Места: допуск вызова (резерв в ведомости); принятие кандидата (граф + каркас + статусы предложений); смена выделения; переход серий; переход каркаса на новую базу.

Т8. Отказ адресный и с маршрутом: что именно, у какого узла, кому возвращается — производителю данных, в пробел M5, владельцу, на пересмотр готовности в M2. Сам отказ ничего не переключает: не разрешает повторное исполнение, не меняет готовность, не открывает новую попытку. Обратные пути идут через G7.

Т9. Каждый пробел заполняется (решение владельца 21.09.2026). Отложенное не теряется и не закрывается без основания; нужное текущей сборке не переносится строкой результата; вес блока — только очередь.
  Места: отсрочка и линии в M5; G4b; M3.

Т10. Продуктовый выбор в коде не делается. Если для исправления надо выбрать СМЫСЛ ограничения (срок жизни бюджета, область потолка, число попыток, замена адресации) — это карточка решения владельца; до решения действует названное осторожное умолчание.

Т11. Политика неизменяема, выданное — копия. Таблицы правил не меняются во время работы; запись, отданная потребителю, не делит изменяемых объектов ни с политикой, ни с источником, из которого ворота выводят эталон. Это требование к модулю; решений схемы оно не меняет.
```

## Передача · M2 → M4 → M7 · горизонт → операции → работы

```text
ЧТО ПЕРЕДАЁТСЯ И ЧТО ПОЛУЧАТЕЛЬ СЧИТАЕТ ДОКАЗАННЫМ

M2 → M4. Запись om-horizon: блоки горизонта; по каждому — refinement (accepted | needed: есть ли принятое настоящее раскрытие) и execution (needed | available с основанием); граница — блоки вне горизонта, у которых есть И результат, И принятое раскрытие; адреса внешних входов; исключения владельца с причиной и условием возврата; хэш (в него входят версия выбора, исключения и основания).
  M4 считает доказанным: горизонт замкнут — каждый производитель, нужный блоку горизонта (по связям данных, requires и передачам владения), либо в горизонте, либо на границе.
  M4 НЕ считает доказанным: что принятое раскрытие означает готовый результат; что квитанции подлинны (это M8).
  Правило: «раскрыт на карте» ≠ «результат есть». Граница — только при обоих признаках. Блок с результатом, но без раскрытия добирается в горизонт РАДИ РАСКРЫТИЯ: исполнять его не нужно, но конкретный подблок-производитель должен быть известен.
  Основание готовности — блок → {артефакт: точная ссылка на квитанцию} на КАЖДЫЙ результат, который у блока берёт горизонт, включая исход выбранной фичи. Одна «квитанция на блок» основанием не считается. Непокрытый результат — адресный отказ (блок и артефакт).

M4 → M7. Принятый слой операций и запись каркаса операций: какой конец какого потока какой связи закрыт каким узлом и портом; какие узлы — представители; хэши слоя.
  M7 берёт ЗОНУ: операции, которые УТОЧНЯЮТ (Т2) блоки горизонта с execution needed. Представитель операции в зону не входит.
  Блок с execution available в зону не входит — повторное исполнение не выводится. Его производители обязаны быть НАСТОЯЩИМИ принятыми работами, а вход от них принимается только по квитанции, которую M2 назвал основанием именно этого результата: квитанция названа на эту работу, с её подписью и хэшем контракта, и она же — текущая квитанция артефакта (иначе компилятор прочтёт другую).
  M7 НЕ проверяет: подлинность коммита, дерева, плана и прогона квитанции — это действующий resolveArtifact на стыке с M8.

ОБРАТНЫЕ МАРШРУТЫ (Т8)
  · Результат «есть», а настоящей работы-производителя нет; либо основание не годится, устарело, названо на чужую работу или не названо вовсе → адресный отказ (связь или ребро, производитель, блок, артефакт) → через G7 пересмотр готовности в M2: исправить основание либо снять признак готовности решением. Автоматически готовность не меняется и повторное исполнение не запускается.
  · Слой операций законно изменён и принят тем же каркасом, когда слой работ уже принят → каркас работ ЯВНО переходит на новую базу: заполнения, чьё обязательство сохранилось, переносятся; остальные уходят в историю; новые обязательства обрабатываются обычным порядком. Правка слоя в обход каркаса — отказ, переход не выполняется.
  · Незаполненное обязательство зоны → адресный пробел в M5 вместе с соседями по связи.

M7 → M9 → компилятор. Граф уровня работ: работы с местом в коде и тестами; привязки уровня работ — действующие и спящие (якорь и тест пробуждения для соседа вне плана); план исполнения = настоящие работы, уточняющие операции зоны; пакет соседей каждой работы. Всё выводится из ОДНОГО зафиксированного снимка графа вместе с записью каркаса работ и основаниями доставки — не из текущих голов записей в момент выдачи задачи.
```

## Передача · M1 и каркасы → M5 · откуда берутся пробелы и куда уходят ответы

```text
ИСТОЧНИКИ — каждый приходит явно; пустой — явно пустой (Т4)
  M1 → M5: пробелы входа с потребителем, названным фичей, требованием или механизмом OM; вопросы предыдущих стадий с тем потребителем и тем видом знания, которые дал производитель (структурированные сведения производителя проходят стык без потерь); хэш версии входа.
  Каркас операций → M5 и каркас работ → M5: незаполненные обязательства ТЕКУЩЕЙ зоны с потребителем-узлом и соседями по связи.
  M5 считает доказанным: набор каждого источника получен и относится к названным версиям входа, графа, каркаса и горизонта (сверка версий — граница модуля: один зафиксированный набор ссылок, к которому относится результат ворот).
  M5 НЕ считает доказанным: что пробел, которого нет в наборе, закрыт. Каркас отдаёт только свою зону, поэтому «исчез из набора» = «вне области проверки», а не «заполнен».

ЧТО M5 ДЕЛАЕТ С ПОЛУЧЕННЫМ
  Одна запись пробела: цель и поле (это её идентичность), вид знания, маршрут, момент разрешения, потребители-блоки, признак «блокирует сборку».
  Потребитель приводится к БЛОКУ горизонта: фича → блоки с её исходом; требование → его фичи; операция или работа → её блок; механизм OM — потребитель-механизм (инвентарь нужен M8 и не откладывается никогда).
  Вид знания и маршрут — по таблице от кода источника; неизвестный код — отказ. Проектное решение нельзя объявить фактом репозитория, и наоборот.
  Потребитель вне горизонта → отсрочка «до входа блока в горизонт»: смена горизонта меняет статус пробела, а не состав.
  «Блокирует» = потребитель действует И вид знания разрешается в проходе OM. Подтверждение среды уходит на старт задачи, доказательство после реализации — на результат задачи: сборку они не держат изначально.
  Несколько источников на одно поле одной цели: одинаковая классификация — одна запись с объединёнными потребителями; противоречащая — отказ, первый источник молча не выигрывает.

КУДА УХОДИТ
  → G4: присланный набор сверяется с выведенным заново (Т3); отсутствие набора — отказ, а не успех (Т4).
  → M6: маршрут по виду знания. → MC2: соседи незаполненного конца связи.
  → G4b: у каждого блокирующего пробела текущей версии входа — ровно один результат законным маршрутом с точной ссылкой. Отложить блокирующий пробел результат маршрута НЕ может: нужное сборке переносит только смена горизонта владельцем.
  → G7: состояние линий. Счётчик проходов линии — не счётчик попыток серии; тот ведётся отдельно (G8).

КАК ОТВЕТ ВОЗВРАЩАЕТСЯ
  · Проектное решение по операциям или работам → предложение слоя в каркас → принятие кандидата → основание закрытия «заполнено».
  · Решение об адресации вопроса (кому он нужен и какого он вида) → новая версия входа → в следующем проходе вопрос становится обязательством СВОЕГО вида. Это не ответ на вопрос. Адресация заполняет только НЕДОСТАЮЩЕЕ: каждое поле, уже данное производителем (вид знания, узел-потребитель), сохраняется; повтор того же решения ничего не меняет; другое решение — отказ. Замена принятой адресации не предусмотрена.
  · Линия пробела закрывается ТОЛЬКО с основанием: «заполнено» (принятое заполнение или адресация, в том числе вычисленное кодом) либо «отменено» (решение владельца). Связать основание с конкретной линией и проверить полномочие отмены обязан поставщик закрытия. Запоздавший проход не отменяет более позднего закрытия или отсрочки.
```

## Правила · M1 и M2 · вход и горизонт

```text
M1 · ВХОД
Получает: принятые записи пяти стадий по точным ссылкам; инвентарь репозитория, если он есть.
Достоверное основание: точная запись стадии (id, ревизия, хэш). Эра записи определяется ВЕРСИЕЙ КОНТРАКТА этой точной записи, а не наличием поля; если порог новой эры введён, а версию определить нельзя — отказ.
Выдаёт и хранит: om-input с хэшем (источники, требования, критерии приёмки, контракты поведения, фичи, вопросы предшественников, состав карты); отказы; адресные пробелы.
Правила: подготовка фичи находится по названию И исходу фичи, а не по месту в списке: нет — отказ, две — отказ, чужая — отказ. Проза вместо id (привязка контракта к блокам, граница, вид проверки) в записи прежней эры — адресный пробел с потребителем; в записи новой эры — отказ производителю стадии. Вопрос без потребителя не создаётся. Догадок нет.
Разрешённые изменения: никаких — M1 только читает. Новая версия входа появляется при новой записи стадии или принятой адресации вопроса.
Отказ и продолжение: отказ G1 — только дефект данных, возвращается производителю стадии; пробелы ворота не закрывают — они идут в M5.

M2 · ГОРИЗОНТ
Получает: принятый верхний слой; выбор владельца {версия выбора, фичи, исключения с причиной и условием возврата}; какие блоки по-настоящему раскрыты; какие результаты готовы и чем это подтверждено.
Достоверное основание: исход фичи существует в карте; исключение обосновано; готовность — точные ссылки на квитанции по каждому нужному результату (подлинность — M8).
Выдаёт и хранит: om-horizon (состав — в передаче M2 → M4 → M7); конфликты; отказы. Хэш не зависит от порядка фич и порядка обхода.
Правила: корни — блоки, производящие исходы выбранных фич; от потребителя к производителю — по связям данных, requires и передачам владения; внешний источник реализации производителя не требует, но адрес входа каждого потребителя сохраняется. Исключённый владельцем блок молча не отбрасывается: если он нужен — это КОНФЛИКТ с путём зависимости, вопрос владельцу: убрать фичу или снять исключение.
Разрешённые изменения: новая версия выбора владельца — новый горизонт (другой хэш); переход серий исправлений на новый горизонт — только после успешного G2 (правила G8).
Отказ и продолжение: неизвестная фича, необоснованное исключение, неподтверждённая или непокрывающая готовность, пустой горизонт → владельцу или поставщику оснований. Повтор той же версии выбора даёт тот же исход.
Открытое: состав доказательства готовности у поставщика оснований — стык с M8.
```

## Правила · M4 · каркас связей операций

```text
Получает: принятый слой блоков; горизонт; принятый слой операций и запись каркаса, если они есть; предложения слоя (от MC2 или выведенные кодом) с указанием базы.
Достоверное основание: верхний слой — принятая запись; принятое соответствие — запись каркаса, привязанная к слою хэшем (Т1); предложение — только в статусе «предложено» и на текущей базе; кандидат — только граф из записи кандидата, прошедший ДЕЙСТВУЮЩИЕ проверки графа и сборки слоя без их правки.
Выдаёт и хранит:
  · обязательства — исход каждого блока и КАЖДЫЙ конец КАЖДОГО потока каждой связи по всему верхнему слою, включая связи внешних артефактов. Поток — привязка, различимая концом-производителем (узел и порт) и якорем; нижние привязки зеркалят верхние по одной (Т6);
  · заполнения с источником: принятое настоящее / предложенное / представитель;
  · кандидат — отдельная неизменяемая запись со ссылками на базу и предложения;
  · после принятия одной транзакцией (Т7) — граф, запись каркаса, статусы предложений.
Правила:
  · очерёдность заполнения: принятое настоящее → предложение → представитель;
  · представитель (тождественный узел 1:1) — только вне горизонта; обязательств горизонта не закрывает; имя зарезервировано — узел предложения не может выдать себя за представителя; несёт только те порты, концы которых закрывает сам; когда блок входит в горизонт, представитель уходит;
  · производитель вне горизонта, нужный узлу горизонта, обязан быть настоящим раскрытием (кроме внешнего источника);
  · предложение несёт полный состав: узлы, заполнения, локальные связи, зависимые определения; все потребители связи доезжают до нижней привязки.
Разрешённые изменения: заполнить пустое; принятое заполнение меняется только ЯВНОЙ заменой с точной базой; зависимое определение принятой части меняется, только если оно названо в предложении; замена не оставляет висящих ссылок; отклонённое предложение повторно не подаётся.
Отказ и продолжение: незаполненное в горизонте → адресный пробел в M5 → MC2 → новое предложение; отказ проверки → предложения отклонены, возврат через G7; база сменилась → новое предложение; запоздавший отказ принятого не меняет; слой изменён в обход каркаса → стоп, владельцу.
Открытое: нет.
```

## Правила · M7 · работы и соседи

```text
Получает: принятый слой операций и запись каркаса операций; om-horizon; предложения слоя работ; квитанции артефактов; поставщика владельцев путей.
Достоверное основание: те же, что у M4 (Т1–Т3), плюс: готовность — только названное M2 основание этого результата; владение путём — подтверждённый прежний писатель с той же границей.
Выдаёт и хранит: каркас работ — ТЕ ЖЕ правила, что каркас операций, уровнем ниже (обязательства: исход каждой операции и каждый конец каждого потока уровня операций, включая локальные связи между подблоками одного блока); граф уровня работ; план исполнения; пакеты соседей.
Правила:
  · Конец связи у настоящей работы привязан к месту в коде — иначе действующая проверка движка откажет.
  · Сосед вне плана исполнения — действующий механизм «спящая связь»: отдельная привязка с якорем и тестом пробуждения. Якорь выводится механически: работа-производитель с исходом = артефакт связи; тест — тест производителя, покрывающий связь. Вывести нельзя — отказ; классификатор возвратов превращает его в адресное проектное решение, если нужен выбор, либо в дефект вывода, если принятое определение потеряно.
  · Пакет соседей ВЫВОДИТСЯ из принятого графа, модель его не присылает. На каждый конец каждой связи работы — запись: связь, артефакт, контракт, направление (читаю / пишу / получаю владение / передаю владение / требую), свой порт и место в коде, порт и место в коде соседа, цепочка соседа работа → операция → блок, маршрут возврата, откуда придут данные: из этого же плана / по квитанции со ссылкой / внешний источник / спящая связь.
  · Адрес подблока — не «где лежит работа», а тот конец верхней связи, который работа УТОЧНЯЕТ (Т2). Уточняет несколько концов — адресов столько, сколько принято и записано в каркасе (Т1, Т6); записи нет — отказ.
  · Представитель помечен честно: операция и контракт обмена известны, работа ещё не спроектирована. Исполнителю не обещается существующий код потребителя; при раскрытии нужны новые привязки и проверка совместимости.
  · Основание результата ищется одинаково для всех видов входа (данные и requires): среди блоков, которые производитель уточняет, — тот, у кого M2 назвал основание этого артефакта; два разных названных основания — отказ.
  · Ровно один пакет на работу; вход без источника задачу исполнителю не пускает.
Разрешённые изменения: как у M4; плюс явный переход каркаса работ на законно изменённый слой операций.
Отказ и продолжение: обратные маршруты — в передаче M2 → M4 → M7.
Открытое: новые проверки атомарности G5 (один писатель, один артефакт, ограниченная область записи, размер пакета) на уровне 2 не раскрыты; управляющий сосед (requires, владение путём) адресуется по расположению работы — у него нет конца связи, который можно уточнять.
```
